# 动画介绍风格

仅在用户选择 `creative_style: animation_explainer` 时读取本文件。再记录一个 `animation_style`：`stylized_3d`、`stop_motion` 或 `motion_graphics`。用户直接说“皮克斯风格”“定格动画”“MG”即可对应子风格，不重复询问；只说“动画”时给出三个简短选项，确认后再生成候选。

## 皮克斯式三维角色动画：`stylized_3d`

用具体美术特征写中文提示词：圆润清晰的角色轮廓、稳定的风格化比例、柔和材质、明确的眼神与小幅表情、可信的接触与重量。可向用户称为皮克斯式三维动画，但不能只写这个名称便省略角色和动作说明。角色从日常问题进入产品使用，通过克制反应表现结果；不自动采用夸张瞪眼、弹跳或大幅变形。

适用 Hook：日常小困扰、结果先行、场景带出产品；两位角色时可用同伴提问。镜头以清楚的角色动作和产品操作为主。有人物时可用角色口头解释或连贯对话，角色讲话保持正常语速。

## 定格动画：`stop_motion`

在候选中确定一种主体材质，例如黏土、纸艺或毛毡，并保持一致。展示可见的手工纹理、稳定接触阴影、清楚的支撑关系和逐帧移动感；主体的形状、比例、颜色及灯光不随帧闪变。分步动作必须完成连续因果，不用随机抖动冒充定格感。

适用 Hook：真实细节切入、操作触发、结果先行、现场演示。机位以固定微缩场景或小幅重新构图为主。微缩环境是用户选定动画媒介的表达方式；复现实际使用空间与生活细节，不添加无关舞台布景和电影光效。

## MG 图形动画：`motion_graphics`

默认无角色，用户要求角色时才设计角色。使用简洁二维形状、清楚层级、连贯路径、遮罩或图形转换表达“问题—操作—结果”。每一段只突出一个变化，保持配色、线条粗细和运动节奏稳定。不强制给抽象画布添加行人、家具、皮肤纹理或摄影光效。

适用 Hook：结果先行、可见反差、现场演示。生成前确认卖点能靠画面讲清；无法表达时缩小到可见步骤或说明该方案的局限，不擅自加字幕、数据图表文字或旁白补救。所有效果必须有真实功能依据，图形变换不能暗示不存在的能力。

## 资产、声音与真实性

- 每位动画角色只生成一张完整参考图，面部与身体同框；多人分别生成，沿用 `CHAR-01` 等 ID。非人角色也按 `character` 资产管理，用可见头部、完整轮廓和配饰定义身份。Seedance 中用 `single_person` 作为角色参考格式，`person`/`featured_person` 也涵盖会表演或说话的动画角色；这些字段是内部绑定，不要求写实人像。
- 产品研究、功能白名单、真实产品照片、App UI 和 App Store 截图仍然必需。动画产品图是视觉表达资产，不能冒充官方照片；产品造型、接口和使用方法需符合真实证据。App UI 继续引用真实截图，不用动画重绘虚构界面。
- 三维和定格场景按真实地点的结构、正常占用和生活痕迹做风格化表达，使用合理普通光线；动画选择仅改变呈现媒介。MG 的 `scene` 资产可为图形画布：固定构图、背景、配色和层级，默认只需一个主视图，无须伪造三维场景的反向或侧视图。
- 抽象 MG 场景仍保存 `normal_state`：占用可写“抽象画布，无现实行人”，生活痕迹可写“不适用：图形解释”，活动写实际图形运动，并在 `exception_reason` 记录用户选定 MG。场景数量统计独立空间或画布，不统计图形每一次变形。
- 不新增字幕、标题、贴纸或解释文字，不加音乐；声音限环境音和可见角色对白。无人 MG 默认用视觉解释，`dialogue: []`、`featured_person: false`、`person_reference_mode: none`；无合理环境音时写“无环境音”，不自动加解说、配乐或装饰音效。品牌和真实界面原有文字按已有规则处理。
- 动画角色使用既有表演字段，描述其设计能表现的小动作与视线；不要给纸片人物强加毛孔、呼吸起伏或人体关节。无角色画面省略表演字段。
- 先确认资产，再出视频提示词；用户确认视频提示词后再做故事版。没有生图能力时提供对应子风格的中文生图提示词。交付、审批、文件完整性规则保持适用。

视频提示词需同时写清子风格的材质/图形语言、一次主要动作、动作结束状态和真实卖点关系。内部枚举放在项目文件，用户拿去生成的提示词用中文。默认模型仍为 Seedance 2.0。
